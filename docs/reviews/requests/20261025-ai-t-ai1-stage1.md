## 무엇을 했는가

1. **데이터 정리:** DOCS `data/` 54개를 SHA-256으로 중복 제거해 50장을 `harness/data/real/photos/real-001~050.jpeg`로 복사했다 (원본 폴더는 그대로, `harness/data/`는 gitignore). 원본 파일명·해시·크기는 같은 폴더 `manifest.json`. 구성: 띠 사진 41장, 전체 사진 9장(세로 배치 5장), 180도 거꾸로 찍힌 사진 1장, 뚜껑이 열려 라벨이 안 보이는 칸이 있는 사진 여러 장
2. **부분 사진 라벨 지원** (`harness/labels.py`): 칸 값에 `not_visible` 허용(모든 칸 필수 규칙은 유지). 사진별 `label_status: confirmed | draft`(기본 confirmed, 기존 합성 샘플 그대로 통과), `check_cells`(초안 작성자가 확신하지 못한 칸). 하네스는 `not_visible` 칸을 모든 정확도 지표에서 빼고, "안 보이는 칸 / 안 보이는 칸을 애매로" 열로 따로 낸다
3. **라벨 초안 + 사용자 확인 시트:** 50장 칸별 초안을 `harness/data/real/labels.draft.json`에 만들었다 (전부 `draft`). **초안은 AI 에이전트(Claude)가 사진을 눈으로 보고 만든 것이고, 시트와 파일에 그 사실과 순환 위험(평가 대상과 같은 계열)을 적었다.** 확인 시트 `harness/data/real/review.html`(생성기 `harness/review_sheet.py`): 사진 + 칸별 버튼(약 있음→빔→안 보임), 확신 못 한 칸 주황 점선, "초안에서 고침" 표시, 사진별 "확인함" 체크, 메모, 진행 상황 브라우저 임시 저장, 불러오기, `labels.json` 내보내기. 서버·네트워크 없이 파일로 열림. 이 Mac에서 열어 렌더링과 칸 전환을 확인했다
4. **확인 전 라벨 숫자 차단:** `draft` 라벨이 하나라도 있으면 `harness.run`이 종료 코드 2로 실행을 거부한다. `--allow-draft`(동작 확인용)로 돌리면 표 위에 "이 표의 숫자는 결과로 쓰지 않는다" 경고가 붙는다. 초안으로 모델을 돌려 낸 숫자는 없다 (mock으로 동작만 확인)
5. **OpenAIReader** (`app/reader/openai.py`): ClaudeReader와 같은 인터페이스·같은 프롬프트·같은 스키마. Responses API + strict JSON 스키마, SDK 없이 httpx(의존성 추가 없음). 키가 없으면 `ReaderUnavailable("OPENAI_API_KEY 가 없음")` → 하네스는 건너뛰고 이유를 적는다. 거절·incomplete·잘못된 JSON은 `ReaderError`(서버에서는 애매로 처리), 429·5xx는 1회 재시도. 단위 테스트 11개(`tests/test_openai_reader.py`, httpx MockTransport, 네트워크 없음)
6. **프롬프트 점검** (`app/reader/prompts.py`, 이유는 파일 주석에도 적음). 세 판독기가 `cells_prompt(layout)` 한 함수로 같은 문장을 쓰게 바꿨다
   - 실사진의 약은 알약이 아니라 접힌 약봉투다 → 알약·캡슐·약봉투(종이·비닐) 형태와 상관없이 "약이 있음"
   - 41/50장이 일부 칸만 보인다 → 칸 위치는 사진 속 순서가 아니라 칸 라벨(요일 글자)로 맞추고, 사진에 없거나 잘려서 안쪽이 안 보이는 칸은 `unclear`. 안 나온 칸의 상태를 짐작하지 말 것 (원칙 5)
   - 약을 꺼낸 칸은 뚜껑이 열려 라벨이 안 보이기 쉽다(실사진 여러 장. 매일 판독의 대상 칸이 바로 이 경우) → 옆 칸 라벨로 위치가 분명하면 그 칸으로 보고 꼭 판단
   - 세로 배치·거꾸로 찍힌 사진 → 방향과 상관없이 라벨로 칸을 정함. 라벨이 한자(月火水…)일 수 있음
   - 라벨 글자, 투명 뚜껑 반사, 비치는 바닥 무늬는 약이 아님
   - 구조 인식(`LAYOUT_PROMPT`)도 같은 이유로 방향·한자 라벨·일부만 보일 때 `uncertain` 문장을 넣었다
7. **비용·지연:** 판독기가 토큰 사용량을 돌려주게 했다(`ReaderMeta.input_tokens/output_tokens`, Claude·OpenAI·Ollama). 하네스 표에 "사진 1장당 비용"(토큰 × `harness/pricing.py`, 2026-10-25 확인 가격과 출처 기록) 열을 추가했다. 지연 p50/p95와 "약 있는데 빈 칸으로 봄" 열은 원래 있었고 그대로 나오는 것을 확인했다 (`--allow-draft` + mock)
8. **로컬 모델 실행 안내:** `harness/README.md`에 사용자 PC(GTX 1660 Super 6GB) 기준 Ollama 설치(Windows·Linux), 모델 pull, 컨텍스트 길이 설정, 저장소·데이터 준비(데이터는 USB 등 직접 복사), Windows PowerShell·Linux 실행 명령, 결과 전달 방법을 적었다. 루트 README에서 링크

## 헌장과 다르거나 애매한 지점

1. **`app/reader/`·`harness/` 밖 변경:** `app/config.py`에 `OPENAI_API_KEY`, `OPENAI_MODEL`(기본 `gpt-5.4-mini`) 설정과 `.env.example` 항목을 추가했다. 또 `ai_external_transfer`(동의 화면의 외부 AI 전송 표시)가 판독기 `openai`도 외부 전송으로 보게 고쳤다. 서버 판독기 기본값은 그대로 `mock`이라 동작은 바뀌지 않는다. 서버 코드와 `design/api.md`에는 특정 회사 이름이 없다. 나중에 서버에서 openai를 쓰기로 하면 앱 동의 화면 문구에 회사 이름이 들어 있는지 FE 쪽 확인이 필요하다
2. **프롬프트는 서버와 공유된다.** 하네스용으로 고친 `CELLS_PROMPT`·`LAYOUT_PROMPT`가 서버의 실제 판독에도 쓰인다 (지금은 mock이라 영향 없음). 확정은 2단계 결과 검토로 한다 (R-010 15번)
3. **토큰 수 저장:** `ReaderMeta`에 `input_tokens`/`output_tokens`(선택)를 더했다. 등록 판독은 `readings.output` JSON에 `model_dump()`로 저장되므로 이 두 값이 같이 들어간다. DB 열·API 응답은 바뀌지 않는다
4. **라벨 규칙(사용자 확인 때 참고):** 칸 안쪽이 보이면 뚜껑이 열려 라벨이 안 보여도 empty/full로 적었다(옆 칸으로 위치가 분명할 때). 사진 가장자리에서 칸 테두리만 보이고 안쪽이 안 보이면 `not_visible`. 일부만 보여도 안쪽 내용물이 보이면 판단했고 `check_cells`로 표시했다. 사용자가 다르게 보면 시트에서 고치면 된다
5. **"이번 칸"(target) 정보가 없다.** 찍은 날짜를 몰라 `target_cell_id`를 비웠다. 그래서 "대상 칸 정확도"는 이 데이터로 낼 수 없다. 대신 뚜껑 열린 칸 같은 하위 집합을 2단계에서 따로 볼 수 있다
6. **약통 1종뿐:** 결과에 "1×7 약통 1종으로만 검증"을 적는다 (계획 문서 1번과 같음). 합성 샘플은 동작 확인용이라 정확도 근거가 아니다
7. **2단계 공정성 관련 질문:**
   - Claude Haiku 5.5·Sonnet 5.5는 thinking이 기본으로 켜져 있다(adaptive). ClaudeReader는 effort를 지정하지 않으므로 모델 기본값으로 돈다. GPT 추론 모델도 기본 추론으로 돈다. 비용·지연 비교에 이 차이가 들어간다. 기본값 그대로 비교하고 결과에 적을지, effort를 맞춰 따로 한 번 더 돌릴지 정해 주면 좋겠다 (제안: 기본값으로 1회, 결과에 명시)
   - OpenAI 후보: 공식 가격 페이지 기준 저가 `gpt-5.4-nano`, `gpt-6-luna`, 중간급 `gpt-5.4-mini`. 비전 입력 지원과 최신 여부는 2단계 시작 때 다시 확인한다
   - 로컬 후보: qwen2.5vl 3b/7b, gemma3 4b, qwen3-vl 4b(있으면). 7b는 6GB를 넘어 일부 CPU로 돌 수 있다. `docker-compose.yml`의 `ollama/ollama:0.5.4`는 오래돼서 README는 직접 설치를 안내했다 (compose 이미지 버전 갱신은 이번 범위 밖)

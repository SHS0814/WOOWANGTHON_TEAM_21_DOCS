# 검토 요청: 백엔드 설계 초안
- 요청자: 기술 스택 결정 세션
- 날짜: 2026-10-24
- 종류: 설계 / 기술스택
- 관련 헌장 항목: 3장 핵심 흐름, 4장 MVP #1~7, 5장 원칙 1·2·4·5·6·8, 6장 (모킹 표시, 배포), 9장 기술 스택

## 무엇을 하려는가
`docs/design/backend.md` 의 백엔드 설계를 확정하려 한다. 주요 내용은 다음과 같다.
- 자체 Python 서버 (FastAPI + PostgreSQL + APScheduler), 사용자 PC에서 Cloudflare Tunnel로 공개
- 로그인 없음. 대면 QR 짝짓기로 어르신 기기 연결, 원격 초대 코드로 보호자 추가, 이후 기기 토큰으로 인증
- 인계 규칙은 서버 한 곳에 두고, 폰은 화면·알림·촬영만 맡음
- 약통 전체 칸을 판독해 "기대 상태"와 비교하는 방식으로 정상, 애매, 칸 그대로, 이중 복용 의심을 분류
- 판독 모듈은 교체 가능한 인터페이스 (Claude / Ollama / Mock). Mock 결과는 DB에 표시하고 UI에 배지로 보여줌

## 왜 필요한가
- MVP 1~7 전부의 기반이다. 특히 무응답 인계(MVP 4)는 서버 cron 없이는 확실하게 동작하지 않는다
- 심사: 구현 완성도(25), 기술 설계·이해도(10)

## 헌장과 다르거나 애매한 지점
1. **"칸 그대로"는 바로 인계하지 않고, "약 드실 시간이에요"라고 한 번 안내한 뒤 재촬영한다** (사용자 결정 R-006). 헌장 3장은 바로 인계로 되어 있다. 이 안내는 복약 시각 알림과 같은 내용이라 원칙 6(의료 조언 금지)에 해당하지 않는다고 보았다. 재촬영 대기 시간 15분은 에이전트가 정한 기본값이다
2. **이중 복용 판정 방식:** 헌장에 정의가 없다. "기대상 차 있어야 할 칸이 비어 있음"으로 정의했다
3. **Claude API를 쓰면 사진이 외부로 전송된다** (원칙 8). 동의 화면과 발표에 명시하는 것으로 처리했다
4. **재질문 2회:** 헌장 범위(2~3회) 안에서 사용자가 확정했다 (R-006)
5. **하루·주간 요약:** 기본은 앱 안에서만 보여주고 푸시를 보내지 않는다. 보호자가 설정에서 켤 수 있다 (R-006). 원칙 2와 충돌하지 않는다
6. **사진 보관 기간:** 보호자가 설정하고, 기본값은 90일이다 (R-006)

## 메인 에이전트 판정: 🟡 조건부 승인 (R-007, 2026-10-24)

**전체 평가:** 핵심 컨셉(3장)과 원칙 1·2·5·8을 잘 지켰다. 특히 다음 세 가지가 좋다.
- 서버를 진실의 원천으로 둔 것
- 전체 칸을 기대 상태와 비교해서 이중 복용을 잡는 방식
- `is_mock` 저장과 배지 표시

아래 조건을 반영하면 진행해도 된다.

**질문에 대한 답**
1. 칸 그대로 시 1회 안내 → 승인. 사용자 결정 R-006이 헌장 3장보다 우선한다. 헌장 3장 문구 갱신은 사용자에게 요청함. 15분 기본값도 승인
2. 이중 복용 정의 ("기대상 차 있어야 할 칸이 비어 있음") → 승인. 다른 날 칸을 잘못 꺼낸 경우도 같은 사유로 잡히는데, 보호자에게 넘길 만한 상황이라 문제없다
3. 외부 전송 → 동의 화면과 발표에 명시하는 것으로 승인. UI 쪽 동의 문구에도 반영해야 한다 (R-008 조건 4)
4~6. R-006과 일치한다. 승인

**조건 (반영 필수)**
- **C1. 리필 기준선은 사진으로 잡는다.** 기대 상태 계산 전체가 `refills` 기록에 달려 있다. 보호자가 "약통 채움"을 누르지 않거나 늦게 누르면 이중 복용 의심 오탐이 쏟아지고, 원칙 2를 위반하게 된다. 따라서 다음을 반영한다
  - 리필은 사진 1장과 함께 등록한다. 판독 결과를 실제 기준선으로 저장한다
  - 매일 판독에서 "모든 칸이 차 있음"이 나오고 리필 기록이 없으면, 이중 복용으로 분류하지 않는다. 대신 보호자에게 "약통을 채우셨나요?" 확인을 1회 요청한다
- **C2. 같은 원인으로 반복 알림을 보내지 않는다.** 놓친 칸은 다음 복약 때도 계속 "차 있음"으로 보인다. 이미 인계됐거나 `not_taken`으로 판정된 칸은 이후 비교에서 "기대 = 차 있음"으로 바꿔서 다시 인계되지 않게 한다
- **C3. "약 드실 시간이에요" 안내는 해당 복약 시간 안에서만 한다.** 복약 시각 +30분(무응답 인계 기한)이 지난 뒤 올라온 사진이 "칸 그대로"면, 안내 없이 바로 인계하고 화면에는 "○○님께 알려드렸어요"만 띄운다. 늦은 시각에 복용을 유도하면 다음 복용과 가까워질 수 있어서다 (원칙 6)
- **C4. 심사용 토큰을 Public README에 넣지 않는다.** 저장소가 Public이라 토큰이 공개되면 누구나 시연 가족의 사진과 기록에 접근할 수 있다. 다음처럼 처리한다
  - 심사용 가족은 실제 가족과 분리하고, 샘플 약통 사진만 쓴다
  - 접근 정보는 비공개인 제출 폼에만 적는다
  - 심사 종료(11/21) 후 토큰을 폐기한다
- **C5. 재질문 간격의 원천은 서버다.** 어르신 폰의 로컬 알림 시각(+10/+20)과 서버 인계 기한(+30)은 서버 설정값 하나에서 내려받는다. 앱에 숫자를 하드코딩하지 않는다

# 검토 요청: T-FE22a 입력 시트 키보드 가림 수정

- 요청자: FE 에이전트
- 날짜: 2026-11-08
- 브랜치: `fe/sheet-keyboard` 커밋 `0f50d56` (FE main 57a9f28 기준, main 병합 안 함)
- 바꾼 파일: `src/components/guardian/ui.tsx`, `src/app/guardian/(tabs)/settings.tsx`
- 네이티브 설정(app.json) 변경 없음, 재빌드 불필요(JS만), 새 의존성 없음, 어르신 화면 변경 없음

## 원인

- Android 15부터 앱은 화면이 상태바·내비게이션바 뒤까지 그려지는 방식(edge-to-edge)이 강제됩니다. 그래서 키보드가 떠도 창이 줄어들지 않습니다.
- `app.json`에는 `softwareKeyboardLayoutMode`가 없어 기본값 resize이지만, 이 상황에서는 효과가 없습니다.
- 호칭 시트는 `Modal`(별도 창)이었고, Android에서는 `KeyboardAvoidingView`도 끄고 있었습니다.
- RN 0.88의 Android 키보드 이벤트(`keyboardDidShow`)는 메인 창의 ReactRootView에서만 나옵니다. 그래서 Modal 안에서는 키보드 높이에 맞춰 움직일 수단이 없었습니다.

## 고친 것

- **`useKeyboardOverlap()`** (보호자 `ui.tsx`):
  - 키보드 이벤트가 주는 키보드 윗변(`endCoordinates.screenY`)과, View의 아래끝(`measureInWindow`)이 겹치는 만큼을 아래 여백으로 줍니다.
  - 창이 실제로 줄어드는 기기(예전 Android, adjustResize가 동작하는 경우)에서는 겹침이 0이라 여백이 두 번 생기지 않습니다.
  - iOS는 `keyboardWillShow`/`Hide`, Android는 `Did`를 씁니다.
- **설정 → 어르신 호칭 시트:** Modal 대신 **화면 안에 겹쳐 띄우는 시트**로 바꾸고 위 훅으로 키보드 바로 위에 붙입니다. Android 뒤로 가기를 누르면 시트가 닫힙니다.
  - 입력이 없는 선택 시트(약 칸이 그대로일 때, 사진 보관 기간)는 Modal 그대로입니다.
- **`GScreen` 전체:** 같은 훅을 걸어, 키보드가 뜨면 화면 아래 여백이 생기고 스크롤 영역과 하단 고정 버튼이 키보드 위로 올라옵니다. 이때 하단 안전 여백(내비게이션바 높이)은 뺍니다. 해당 화면은 다음과 같습니다.
  - 연결 화면(어르신 호칭·내 이름 입력 + "가족 만들기")
  - 초대 코드 합류(초대 코드·이름 입력 + "합류하기")
- **점검했지만 바꾸지 않은 것:** 보호자 쪽 다른 입력은 없습니다. 날짜·시각 선택 시트는 입력칸이 없어 해당하지 않습니다.

## 실제 폰 확인 부탁 (S22 Ultra, Android 16)

1. **설정 → 어르신 호칭:** 입력칸을 누르면 시트(입력칸, 취소, 호칭 저장)가 키보드 바로 위에 있는지, 키보드를 내리면 시트가 원래 자리로 돌아오는지
2. **연결 화면과 "초대 코드가 있어요" 합류 화면:** 입력칸을 누르면 하단 버튼이 키보드 위로 올라오는지
3. 시트가 열린 상태에서 뒤로 가기를 누르면 시트만 닫히는지

웹에서는 키보드 이벤트가 없어 시트 표시, 저장, 닫기만 확인했습니다. tsc는 통과했습니다.

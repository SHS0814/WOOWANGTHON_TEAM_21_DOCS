| Q-002 (낮음) 공백 이름 | 버그. strip한 뒤에 길이를 검증한다. 같은 패턴 3곳 모두 고친다 | BE |
| Q-003 (낮음) 어르신 글씨 크기 | 일부 버그. 기준을 이렇게 정한다. ① **어르신이 읽는 정보와 버튼 글씨는 28pt 이상**: E8 "○○ 판정" 배지, E2 [숫자로 연결] 버튼 ② **모의·시뮬레이션 표시는 18pt 이상이면 된다**: 상단 띠, "모의 결과" 배지, "시뮬레이션" 표시. 이건 심사·시연용 표시이고, 어르신 정보를 가리지 않아야 해서다. E8 배지는 정보 부분("○○ 판정", "AI 확인")과 모의 표시 부분을 나눈다 | FE |
| **Q-004** (보통) 늦은 정상 사진인데 E8은 기록 없음 | **계약 변경.** 늦은 사진이 정상 판독이면 **어르신 기준 `elder_status = recorded`**로 하고, `taken_at`은 사진 촬영 시각으로 둔다. 보호자 인계는 지금처럼 열어 두고 `late_photo: true`로 표시하며, 판정은 보호자가 한다. 어르신에게 "기록해 뒀어요"라고 말한 뒤 "아직 기록이 없어요"를 보여주는 것은 이중 복용을 부를 수 있다. 이 앱이 막으려는 바로 그 위험이다 (1장, 원칙 6) | BE (api.md 2.5 표와 3.18 수정) |
| Q-005 (낮음) 재촬영 두 번 | 버그. **한 복약 건에서 어르신에게 다시 찍어 달라고 하는 것은 종류(애매 재촬영, 칸 그대로 안내)와 관계없이 최대 1회**다. 두 번째 사진도 정상이 아니면 보호자에게 넘긴다 | BE (backend.md 7장 명시) |
| Q-006 (낮음) G5 안내 사실 누락 | 개선. `DoseEvent`에 `reminded_at: string \| null`을 추가한다 (보호자 응답에서만 값을 채우고, 어르신 응답에서는 null). FE는 이 값이 있으면 "약 드실 시간이라고 한 번 안내했어요"를 보여준다 | BE 필드 → FE 문구 |

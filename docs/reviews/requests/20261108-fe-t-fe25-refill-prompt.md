## 1. 어르신 E7a (사용자 결정 기능, 최소 변경)

- `elder/reading/[id].tsx`: 사진 응답의 `refill_prompt`를 결과 화면 파라미터 `refill`로 넘깁니다. 추가한 줄은 2줄입니다.
- `elder/result/[id].tsx`: `kind=done`(E7a)이고 `refill`이면, 기존 "고마워요. ○○ 약 기록해 뒀어요." 아래에 **"약통을 채워 주세요."** 한 줄을 보여 줍니다.
  - 글자는 기존 `elderBody` 변형(28pt)이고, 가운데 정렬입니다.
  - 버튼은 없고, 5초 뒤 자동으로 홈에 가는 동작도 그대로입니다.
  - 다른 결과(E7b·c·d)와 다른 어르신 화면은 바꾸지 않았습니다.
- 의료 지시 문구는 없습니다. 약통을 채우라는 말만 하고, 약을 더 드시라는 말은 하지 않습니다.
- 이전 서버가 이 필드를 보내지 않으면 없는 것으로 보고 한 줄을 보여 주지 않습니다(타입에서 선택 필드로 둠).

## 2. 보호자 설정 (G8)

- "약통과 시각" 묶음의 "약통 채우기" 아래에 스위치 **"약통 채우기 안내를 어르신께 보여 드리기"**(`elder_refill_prompt`)를 추가했습니다. 바꾸면 바로 `PUT /settings`로 저장합니다(기존 하루 요약 알림 스위치와 같은 방식).
- 아래 설명 줄:
  - 켜짐: 마지막 칸을 쓰면 어르신 화면에 "약통을 채워 주세요"가 나와요
  - 꺼짐: 약통은 보호자가 채워요. 남은 칸이 적으면 홈에서 알려 드려요

## 3. 하루 약통 등록 (G2)

- `POST /pillboxes`가 성공하고 약통이 하루 약통(`pillboxKind = daily`, T-FE18 규칙)이면 `PUT /settings { elder_refill_prompt: true }`를 보냅니다.
- 약통 등록은 이미 끝났으므로, 이 저장이 실패해도 등록 흐름(기준선 확인 → G3)은 막지 않습니다. 보호자는 설정에서 켤 수 있습니다.
- 일주일 약통을 등록할 때는 값을 건드리지 않습니다(지시 범위). 하루 약통에서 일주일 약통으로 바꾸면 켜진 값이 남습니다. 끌지 말지는 판단을 부탁드립니다.

## 4. 보호자 홈 '다음 할 일'

- 기본은 **다음 복약**(시간대·시각, 기존 `today.next_event`)입니다.
- **약통 남은 칸 행**은 `elder_refill_prompt`가 false이고 `needs_refill`일 때만 보입니다. 보일 때는 "약통 남은 칸 n칸 · ! 곧 채워야 해요."이고, 누르면 약통 채우기(G7)로 갑니다.
  - 설정을 못 읽으면 기본값 false로 봅니다(3.26).
  - `pillbox_mismatch`는 이 행이 보일 때 문구에 함께 붙입니다. **행이 숨겨진 경우 홈에는 "약통 상태가 기록과 달라요"가 나오지 않습니다**(G7 화면에는 그대로 나옴). 이 동작이 괜찮은지 확인 부탁드립니다.
- 다음 복약도 없고 리필 행도 없으면 '다음 할 일' 영역 자체를 숨깁니다.
- 약통 상태(`currentPillbox`)도 다른 홈 데이터처럼 주기적으로 다시 읽게 했습니다.

## 5. 모의 API

- 설정에 `elder_refill_prompt`(기본 false)를 추가했습니다. 시드 가족은 시드 약통이 하루 약통이라 true로 시작합니다(하루 약통 등록과 같은 상태).
- 사진 응답 `refill_prompt` = `result === 'recorded'` && 설정 켜짐 && 기록 뒤 남은 칸 0. 남은 칸은 `currentPillbox`와 같은 계산을 `remainingSlots()`로 뽑아 함께 씁니다. 그래서 하루 약통의 저녁 정상 기록이면 true입니다.

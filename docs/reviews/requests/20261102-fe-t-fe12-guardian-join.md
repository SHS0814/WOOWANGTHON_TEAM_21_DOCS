1. **G1 첫 화면(`src/app/guardian/connect.tsx`)** 에 "초대 코드가 있어요" 버튼. 초대 코드와 내 이름을 넣어 `POST /pair { code, display_name, platform }` 하면 보호자 홈으로 간다. "가족 만들기로 돌아가기" 있음. 토큰이 이미 있을 때(설정 → 어르신 폰 연결)는 이 경로가 보이지 않는다
2. **입력:** 코드만 넣어도, 링크(`woowang://pair?code=…`)째 붙여넣어도 된다. 공백은 지운다. 코드가 대소문자를 구분하므로 이 칸은 자동 대문자·자동 고침을 끈다 (`Field`에 `verbatim` 추가)
3. **오류 안내:** 틀린 코드 / 만료 / 이미 쓴 코드 / 시도 제한(429) / 네트워크. 만료·사용은 "처음 보호자에게 새 코드를 받아 주세요"
4. **6자리 숫자:** 어르신용 예비 코드라 서버에 보내지 않고 바로 안내한다 (시도 제한 횟수를 쌓지 않으려고)
5. **모의 서버(`src/api/mock.ts`):** 보호자 합류 추가. 앱에 초대 코드를 만드는 화면이 없어(범위 밖) 고정 값을 쓴다: `mock-invite`(합류), `mock-expired`, `mock-used`, `mock-limit`, `mock-elder`(어르신 코드). 합류 화면의 "개발용: 모의 초대 코드 넣기 (실제 서버 아님)"는 mock 모드에서만 보인다
6. **정리:** QR 값 파싱을 `src/lib/pairCode.ts`로 옮겨 `elder/connect.tsx`와 함께 쓴다. 잘못된 `%` 표기에서 `decodeURIComponent`가 던지던 경우도 막았다

### 구현 중 막은 함정 2개

- **합류 직후 어르신 코드 발급:** 기존 G1은 토큰이 생기면 자동으로 `POST /pairing-codes {kind:"elder"}`를 부른다. 합류에 그대로 태우면 그 가족의 유효한 어르신 코드가 무효가 된다. 합류 모드에서는 부르지 않는다 (아래 표에서 확인)
- **합류 후 푸시 등록 누락 가능성:** `http.ts`는 `pair`의 토큰 저장보다 먼저 변경 알림을 보내서, 보호자 레이아웃의 등록 시도가 토큰 없음으로 끝날 수 있다. 합류 성공 뒤 `registerGuardianPush()`를 직접 부른다. **Android 기기 확인은 못 했다** (아래)

### 확인 못 한 것

- **Android 실기·에뮬레이터 전체** (지시대로 설치하지 않음). 그래서 실제 키보드의 자동 대문자 해제, 합류 후 `PUT /devices/me/push-token`, Android 뒤로 가기는 코드로만 봤다. 웹에서는 푸시가 `unsupported`라 등록 요청이 나가지 않는다. **에뮬레이터 첫 합류 때 서버 로그의 `PUT /devices/me/push-token`과 G8 알림 상태를 봐 주기 바란다**

## 헌장과 다르거나 애매한 지점

1. **남는 위험 (판단 요청):** `POST /pair`는 코드 종류를 서버가 정하고 앱이 "보호자로 합류"라는 의도를 보낼 수 없다. 그래서 22자 **어르신** 코드를 이 칸에 넣으면 서버가 이미 어르신 기기를 만들고 **기존 어르신 기기를 해제**한 뒤에야 앱이 알 수 있다. 앱은 토큰을 버리고 안내만 할 수 있고, 어르신 폰은 다시 연결해야 한다. 어르신 코드는 QR 안에만 있어 사람이 이 칸에 넣을 일은 드물다고 보고, 계약을 바꾸지 말라는 지시대로 그대로 뒀다. 막으려면 BE·계약 변경이 필요하다(예: `/pair`에 기대하는 kind를 보내고 다르면 거절)
2. **`src/app/elder/connect.tsx`를 건드린 이유:** 파싱 함수를 옮긴 것뿐이다. 동작은 잘못된 `%` 표기에서 던지지 않는 점만 다르다

# 프로젝트 헌장 (Project Charter)

> 이 문서는 프로젝트의 "큰 틀"이다. 모든 계획·코드·설계는 이 문서에 비추어 메인 에이전트가 검토하고 승인한다.
> 이 문서의 변경은 사용자(프로젝트 오너)만 결정한다.

- 작성일: 2026-10-24
- 대회: 2026 AI 우왕톤 (충북대 AI부트캠프사업단 × 멋쟁이사자처럼 충북대)
- 대회 주제: **"AI는 동료가 될 수 있을까?"** — AI가 반복 업무를 먼저 처리하고, 최종 결정은 사람이 한다
- 팀: 1인 개발 (사용자) + Claude 에이전트들

## 1. 문제 정의

치매는 가장 최근의 기억부터 잃는다. 따로 사는 치매 어르신은 **오늘 약을 먹었는지 스스로 기억하지 못한다.**
그 결과 복용 누락과 **이중 복용** 위험이 생긴다.

현재 실제 사례(오너의 가족):
- 보호자(아들)가 복약 시간을 기억하고 어르신께 연락해 **약통 사진을 찍어 보내달라고 요청**한다
- 보호자가 사진을 보고 복용 여부를 직접 판단한다
- 보호자가 매주 방문해 약통을 채운다
- 이 과정은 어르신과 보호자가 서로 믿고 협조하기 때문에 성립한다. 대신 보호자가 매일 직접 처리해야 해서 피로가 쌓인다

근거 자료 (발표 부록용):
- 국내 치매 환자 약 97만 명(2025), 독거 가구 유병률 10% (배우자 동거 4.9%의 약 2배): https://weekly.khan.co.kr/article/202503121436001
- 치매 환자 가족 45.8%가 돌봄 부담 호소 (같은 출처)
- 치매 치료 시작 환자 44%가 1년 내 복용 중단 (중단 사유 포함 수치임에 유의): https://medicalworldnews.co.kr/m/view.php?idx=1510970261
- 혼자 사는 경도 치매 환자의 화상 복약 모니터링 시 순응도 81% vs 대조군 66% (Smith et al., 2007, 모니터링 그룹 8명의 소규모 연구): https://pmc.ncbi.nlm.nih.gov/articles/PMC10697209

## 2. 대상 사용자

- **어르신:** 보호자와 협조 관계가 있는 경도·초기 치매 어르신, 혼자 또는 낮 시간에 혼자 지냄, 요일별 약통 사용
- **보호자:** 따로 사는 가족. 언제든 기록을 볼 수 있지만, **예외 상황에서만** 개입한다
- 비협조 단계나 중증 단계는 대상이 아니다. 이 경우 앱은 보호자에게 인계만 한다

## 3. 핵심 컨셉 (변경 불가 축)

**앱은 지금 보호자가 하는 역할(기억하고, 물어보고, 사진을 확인하는 일)을 대신하고, 예외만 보호자에게 넘긴다.**

```
약 시간 → 앱이 어르신께 물어봄 → 약통 사진 → AI 판독
   ├─ 정상 → 조용히 기록 (보호자는 요약만 받음)
   ├─ 무응답 → 재요청 2회 → 그래도 없으면 보호자 인계
   ├─ 판독 애매 → 재촬영 요청 또는 보호자 판정 요청
   ├─ 칸이 그대로 → 보호자 설정에 따라
   │     · (기본) "약 드실 시간이에요" 1회 안내 후 재촬영 → 그래도 그대로면 보호자 인계
   │     · 바로 보호자 인계
   └─ 이중 복용 의심 → 보호자 인계
보호자가 최종 판단 (전화, 방문 등)
```

## 4. 기능 범위

### MVP (반드시 구현)
| # | 기능 | 설명 |
|---|---|---|
| 1 | 앱이 물어보기 | 복약 시간에 전체 화면으로 질문, 무응답 시 재요청 |
| 2 | AI 약통 판독 | 사진에서 해당 요일·시간대 칸이 비었는지 판단 (**범용 약통 지원**, 5장 참고) |
| 3 | "나 약 먹었나?" | 어르신이 누르면 오늘 복용 기록을 시각과 사진으로 보여줌 (이중 복용 방지) |
| 4 | 단계적 인계 | 무응답, 판독 애매, 칸이 그대로, 이중 복용 의심일 때만 보호자에게 알림 |
| 5 | 보호자 판정 | AI가 애매하다고 한 건을 보호자가 "드심 / 안 드심"으로 판정하고 기록에 반영 |
| 6 | 하루·주간 요약 | 보호자용 요약 (정상일 때는 짧게) |
| 7 | 약통 리필 알림 | 남은 칸 수를 기준으로 리필 시점 안내 |

|---|---|
| 8 | 연락두절 감지: 어르신 앱이 일정 시간 응답하지 않으면 보호자에게 알림 |

### 범위 밖 (구현 금지, 발표에서 "확장 계획"으로만 언급)

- 위치 추적, 배회 감지
- 병원·약국 연동, 처방 정보 연동

## 5. 설계 원칙 (검토 기준)

1. **AI는 동료, 결정은 사람.** AI는 판독하고 분류하고 요약한다. 보호자에게 넘길지는 규칙으로 정하고, 최종 판단은 보호자가 한다
2. **보호자 피로 최소화.** 정상 상황에서는 알림을 보내지 않는다. 알림이 늘어나는 설계는 거절 사유다
3. **어르신 존엄.** 감시가 아니라 가족이 물어보는 대화 말투를 쓴다. 큰 글씨, 한 화면에 한 가지 행동만, 최소한의 조작
4. **범용 약통 판독.** 특정 약통 모델에 하드코딩하지 않는다. 칸 수와 배열(요일만, 요일×시간대 등)이 다른 약통도 처리해야 한다. 최초 1회 약통 등록(구조 인식과 사용자 확인) 같은 방식은 허용한다
5. **불확실하면 추측하지 않는다.** 판독 신뢰도가 낮으면 "복용"으로 처리하지 않고 재촬영을 요청하거나 보호자에게 넘긴다
6. **의료 조언 금지.** 앱은 "지금 한 번 더 드세요"나 용량 안내를 하지 않는다. 기록하고 보호자에게 넘기는 것까지만 한다. 놓친 약에 대한 판단은 보호자와 의료진의 몫이다
7. **한계를 정직하게 표시.** 사진은 "칸이 비었다"까지만 보여준다. 삼켰는지는 확인하지 못한다. 이 한계를 UI와 발표에 명시한다
8. **개인정보.** 약통 사진과 복약 기록은 민감 정보다. 어르신 본인의 동의 흐름을 두고, 해당 가족만 접근할 수 있게 한다
